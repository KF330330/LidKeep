# LidKeep 合盖运行

本机自用的 macOS 菜单栏程序。通过系统 `pmset` 控制合盖休眠，让现有 Codex、Claude Code 会话有机会在合盖后继续运行。包含原生 Swift App、root 电源服务和独立监护服务；只用 Apple 系统组件，无第三方依赖或下载。

**首次安装保持正常休眠，先通过短时合盖验收才会进入默认常开。** 普通 `caffeinate` 不能证明合盖可用；本程序也不会把任务断网或授权等待当作已经解决。兼容性必须在实际机器上验证。

## 构建与安装

需要 Apple Silicon Mac、macOS 14 或更新版本，以及提供 Swift 6 的 Xcode / Command Line Tools。当前开发机器为 M2 Max、macOS 26.5。

在项目目录以普通用户执行：

```sh
bash scripts/test.sh
bash scripts/build.sh
bash scripts/check-packaging.sh
open dist/LidKeep.pkg
```

安装器通过 macOS 标准管理员授权安装至 `/Applications/LidKeep.app`。安装完成后打开该 App，按菜单中的合盖验收流程操作。请使用安装包，不要直接从 `dist` 运行 App；后台仅接受安装版本的代码签名。

1.1.0 新增自动合盖资源诊断：默认开启，每 5 秒检查合盖状态，合盖期间每 30 秒记录系统内存、压缩内存、交换区、内存压力、CPU、热状态与进程占用排名；合盖、开盖及观测到热状态／运行状态变化时补采。菜单可关闭自动诊断、立即检查、查看／导出报告和打开日志目录。详见 [合盖诊断](docs/diagnostics.md)。

1.0.3 修复原子替换状态文件时，读者仍持有旧文件却被误判为权限异常的竞争条件。已经打开的安全快照允许被原子替换；文件权限、所有者、符号链接及硬链接检查继续生效，电源锁与保护锁仍保持严格校验。后台日志增加状态变化原因、系统休眠／唤醒与菜单栏断线事件。

1.0.2 使用选定的 A33「织带」应用图标与 M03「无限」菜单栏图标。菜单栏只显示 18pt 的单色 ∞，使用系统标准方形占位；运行状态、电量、温度与原因仍可在展开菜单中查看，悬停提示和 VoiceOver 标签也包含当前状态。构建脚本通过 AppKit/CoreGraphics 与系统 `iconutil` 生成图标，不依赖第三方绘图库。

1.0.1 修复了首次安装时后台被 macOS 终止的问题。安装器会在管理员拥有的目录中创建字节一致的本机可执行文件、核对签名，再原子替换目标文件；它不改变 Gatekeeper 或 SIP。打包检查增加实际执行的只读自检。若 1.0.0 曾安装失败，直接运行新版安装包即可重试，无需先卸载。

这是本机生成的临时代码签名程序和未签名安装包，没有 Developer ID 或公证；不会修改 Gatekeeper、SIP 或系统安全策略。构建产物为 `dist/LidKeep.app.zip` 和 `dist/LidKeep.pkg`。菜单栏程序不显示 Dock 图标。

当前“文稿”目录的文件同步服务会给未压缩的 `.app` 添加 Finder 元数据，影响严格签名验证，因此 App 以 ZIP 交付。构建、签名和解包检查在 `/private/tmp` 完成；优先用 PKG 安装到 `/Applications`，不要在同步目录解压运行。构建输出还会显示一个临时原生 App 预览路径，该路径可能被系统清理。

## 使用规则

- 首次运行注册登录启动；可在设置中调整。如系统要求授权，在“系统设置 → 通用 → 登录项与扩展”完成。
- 合盖验收通过后默认启用。手动关闭会持久保存，重开 App 或重启电脑不会自动覆盖。
- 开启时允许屏幕熄灭。电量**严格低于 10%**、系统热状态达到 `serious / critical` 时，解除保活并请求整机休眠；10% 本身不触发低电量保护。
- 保护后恢复需要电量至少 **20%**，且热状态保持 `nominal` **60 秒**。手动关闭优先于自动恢复。可自定义电量阈值，恢复值必须高于停止值。
- 一次保护只主动请求一次休眠；用户唤醒后不会因同一次保护反复被迫休眠。本程序不安排定时唤醒。
- 电池数据失效、服务故障或菜单栏 App 失联会撤销保活。心跳每 5 秒，失联阈值 30 秒；监护服务也会检查后台失联。
- “立即休眠”先恢复休眠设置，再请求整机休眠。再次唤醒同样等待恢复电量和 60 秒正常热状态，再重新保活。退出 App 后保活会随心跳失效撤销。

现有两项 `caffeinate` 服务保持原样。系统休眠保留程序和窗口，但不能保证远端请求在恢复后不断线。通勤时仍需热点保持联网。

## 升级与卸载

升级时重新构建并打开新的安装包。安装脚本先进入维护状态、恢复旧服务持有的电源设置，再停止旧服务和替换程序；升级后重新打开 App。若恢复失败会中止，不会强行覆盖其他来源的 `SleepDisabled=1`。

卸载前先在菜单设置中关闭登录启动，再退出 App，然后在“终端”执行已安装的卸载器：

```sh
sudo '/Library/Application Support/LidKeep/uninstall.sh'
```

卸载器在服务仍存在时先恢复设置，再停止两个服务、再次确认恢复，最后只删除 LidKeep 自己的 App、后台、清单和状态。不会移除其他 `caffeinate` 服务。卸载也会删除 LidKeep 的偏好及验收记录。

## 验证与边界

自动化测试覆盖策略和故障逻辑；安装包结构、签名、脚本语法可在不安装的情况下检查。**实机合盖、电池供电、热点、实际 AI 请求、温控、重启与卸载的系统行为需要按 [验收步骤](docs/acceptance.md) 手动确认。** 开发过程中的编译通过不能替代这些测试。

本次交付完成 47 项自动化测试和一轮 Claude 跨模型审查；成立问题、未采纳理由及验证范围见 [审查记录](docs/review.md)。

系统热状态反映 macOS 的热管理压力，并非独立硬件温度报警器。应把电脑放在通风处，不要把温控保护理解成可以在密闭包里长期运行。恢复、监护依赖内核和 launchd 正常工作，无法保证内核冻结或硬件故障时仍能执行。

Apple 参考：[防休眠接口与合盖限制](https://developer.apple.com/library/archive/qa/qa1340/_index.html)、[Mac 使用温度与通风](https://support.apple.com/en-us/102336)。
