# 本机验收记录与操作步骤

此文档是可重复的验收清单，不是已完成的实机验收报告。不要在未实际观察到合盖持续运行时确认成功。

## 先检查构建产物

运行 `bash scripts/test.sh`、`bash scripts/build.sh`、`bash scripts/check-packaging.sh`。这些命令不安装服务、不改系统电源配置。产物是 `dist/LidKeep.pkg` 与 `dist/LidKeep.app.zip`；签名验证会在不受“文稿”文件同步影响的系统临时目录分别解包检查，并核对两者与后台的身份清单。

从 1.0.1 开始，解包检查还复用安装器的本机可执行文件创建流程，并实际执行后台 `--diagnose` 和 App `--self-check`；静态签名检查通过不再作为“能启动”的替代证据。

安装前用 `/usr/bin/pmset -g` 确认 `SleepDisabled` 为 `0`。若为 `1` 且并非本程序已持有的设置，安装器会中止；先停用原有禁用休眠工具，避免覆盖其设置。`pmset -g assertions` 可只读核对现有 `caffeinate` 断言；不应删除它们。

## 首次 3 分钟合盖测试

1. 在通风桌面上操作，保证电量高于恢复阈值，系统热状态正常；拔掉外接显示器和电源，连接手机热点。
2. 打开已安装的 App，确认状态为“等待合盖验收”、实际 `SleepDisabled=0`，然后从菜单启动短时测试。先保持开盖，等菜单明确显示“合盖测试中”、实际 `SleepDisabled=1` 后再合盖。
3. 让 Codex 或 Claude Code 执行一个已授权、能观察进度的长任务，记下合盖前输出时间。测试不会自动向 AI 工具发送提示，也不会接管它们。
4. 按 Control–Command–Q 锁屏，合盖约 60–90 秒，再打开屏幕。观察服务的测试证据与 AI 输出时间：应在合盖期间持续有进展，热点未断开，系统没有进入睡眠。可用 `pmset -g log` 核对该时段睡眠记录。另确认屏幕可以熄灭、开盖后需要解锁。
5. 在测试结束后检查已自动恢复正常休眠；只有看过连续运行证据、网络和实际任务均符合预期，才确认测试成功。成功后开启常规保活。
6. 若观察到睡眠、任务停顿、断网或无法判断，取消或确认失败。检查 `SleepDisabled=0`，保持未通过状态；不启用默认常开。测试有 180 秒上限，失联时提前撤销。

只有用户能够确认热点、实际 AI 任务和物理合盖状态的完整结果；系统电源设置的读回成功本身不代表兼容性通过。

## 功能场景

| 场景 | 预期 |
| --- | --- |
| 电量 11%、10%、9% | 前两者不触发低电量保护，9% 触发 |
| 保护后 19% / 20% | 19% 不恢复，20% 且 nominal 持续 60 秒才恢复 |
| nominal → fair → nominal | 恢复计时重置，重新累计 60 秒 |
| serious / critical | 先恢复电源设置，再请求一次休眠 |
| 保护后手动唤醒 | 同一次保护不反复主动休眠 |
| 手动关闭后充电、重启 | 保持关闭 |
| 电池数据无效、未知热状态 | 撤销保活并显示原因 |
| App 被退出或挂起 | 最后心跳 30 秒后撤销保活，允许最多一个采样间隔延迟 |
| 后台崩溃或挂起 | 监护撤销持有的设置；重启不会绕过保护或验收 |
| 立即休眠 | 恢复设置成功后休眠，窗口及程序保留 |

低电量、热状态和故障状态优先用策略层测试模拟，不建议通过堵塞散热制造高温。实机故障注入只在桌面有人看护、能打开终端恢复时执行。

## 系统集成场景

- 分别验证锁屏、显示器熄灭、合盖、开盖、拔插电源；显示器熄灭时任务应继续。
- 检查登录启动；手动关闭后注销登录或重启，确保偏好保留。
- 更新安装时确认恢复旧状态；安装失败应停留在维护状态，不得开启保活。
- 正常卸载、保活开启时卸载、后台故障后卸载，都需确认 `SleepDisabled=0`、两个 LidKeep 服务已退出。
- 对照安装前后的 `pmset -g assertions` 与系统服务，确认原有 `caffeinate` 未被替换、停用或删除。
- 若命令失败或无法恢复，保留安装文件和状态，用错误信息诊断；不要删除后台后再尝试恢复。

每次更换系统大版本、硬件或网络连接方式，都应重新执行物理合盖测试。验收记录建议写明日期、系统版本、电源/网络条件、合盖时长和实际任务结果。
