## 审查方式

按用户全局规则执行了一轮 Claude 只读跨模型审查。原始需求单独保存，不混入实现说明或测试结论；代码按模块拆为 7 份，每份不超过 500 行 diff。工作区开始时没有提交，因此新文件以 `git diff --no-index /dev/null <文件>` 生成等价新增 diff。

首次 CLI 尝试受登录沙箱和无效输出影响；默认模型随后报告额度已用尽。使用已安装的 Claude CLI、现有授权与 Sonnet 完成全部 7 个模块的有效审查，没有购买额度或安装软件。这些重试使用同一原始快照，不是对修复结果反复送审。修复后未再送审。

原始审查输出属于本地过程记录，未随公开仓库发布。Claude 共给出 9 条编号意见，核实后采纳 4 条、未采纳 5 条；另采纳一条登录提示疑问。编号沿用审查者原文，不把每个“P1”都认定为真实高危问题。

## 已修复

| 来源 | 问题与处理 |
| --- | --- |
| interfaces P3 | JSON 编码异常时可能留下待回调记录。改为先编码，再建立连接和登记回调，避免重复回调。 |
| app P1 | 短时测试尚未确认保活生效时显示不清楚。现在显示“验证中”，明确要求等待实际生效再合盖，并允许取消。 |
| app P2 | 心跳刷新可能重启用正在保存的设置按钮。保存状态独立保留，收到回调才恢复按钮与输入框。 |
| packaging P2 | 安装第二个后台失败时可能留下第一个后台。失败路径先恢复休眠，成功后停止本工具服务并再次恢复；恢复失败保留维护状态与修复材料。 |
| app 疑问 3 | 登录注册失败可能被普通状态覆盖。错误现在独立保存并显示在设置页。 |

内部集成复核还发现并修复了 1 处影响保护动作可靠性的重要问题：监护在撤销电源设置后、请求休眠前崩溃，可能丢失已授权的休眠动作。现在用持久化令牌保存请求，App 与监护共用同一令牌去重；恢复所有权记录被清除后仍能完成请求。增加 5 项回归测试，覆盖崩溃窗口、过期心跳、手动请求去重、维护状态与跨系统重启失效。

## 未采纳及疑问核对

| 来源 | 核实依据 |
| --- | --- |
| interfaces P1、P2；coordination P2 | 审查者把未出现在当前分片中的后台、入口和测试误判为缺失。它们实际存在于其他分片；完整工程编译成功，47 项测试通过。 |
| packaging P1 | 审查者推测 `pkgbuild --ownership recommended` 会产生非 wheel 的 App 文件。当前机器实际产物 BOM 全部为 UID 0 / GID 0，打包归属校验通过，推测不成立。 |
| policy P1 | 原始需求没有要求手动休眠后立即恢复。保留唤醒后的恢复阈值和 60 秒稳定期，避免尚未真正睡下时被保活覆盖；状态显示请求休眠/恢复等待，使用说明已明确该行为。 |
| XPC API 疑问 | 当前 Apple SDK 的 NSXPCConnection/NSXPCListener 公开声明支持代码签名要求（macOS 13 起），项目最低 macOS 14，已实际编译。 |
| AppKit 回调线程 | ServiceClient 将状态与完成回调派发到主队列。 |
| 未验收开关 | 策略层即使偏好为开启，也必须通过本机验收才输出常规保活请求。 |
| 锁和保护竞态 | 电源锁有 9 秒上限，保护锁有 3 秒上限；保护版本比较后清除，修改前再次采样。令牌与回执在进程间去重。对应策略及运行时测试已覆盖。 |
| 日志、原因覆盖 | 两服务使用不同日志文件，各自从串行执行路径写入。最新保护原因替换旧原因，但不会清除休眠请求。 |
| 未形成首份心跳时挂起 | 服务在允许启用前写入监护身份及心跳；无法验证进程身份时不按猜测 PID 杀进程。极端内核或存储故障不属于可保证的恢复范围。 |
| sleepnow 失败重试 | 休眠回执在系统命令前持久化，保证每次保护至多主动请求一次；命令失败显示故障，不自动重试同一请求。无法把持久化写入与 macOS 系统调用做成原子事务，不能承诺内核故障下恰好执行一次。 |

## 验证范围

- 21 项策略测试：11% / 10% / 9%、20% 恢复与连续 60 秒、热状态、无效数据、手动关闭持久化、测试自动回退与验收门槛。
- 26 项服务测试：模拟 pmset 失败/假成功、恢复记录、保护去重、GUI/后台失联、过期租约、锁超时、跨进程保护版本、维护状态与持久化休眠请求。
- release 构建；安装包与 App ZIP 的严格签名、身份哈希、hardened runtime、无额外 entitlement、root:wheel 归属、脚本和 plist 校验。
- 实机只读采样：电池、热状态、合盖传感器、显示器、网络路径和 SleepDisabled。

以上测试没有伪造真实低电量/过热，没有替代实机合盖验收。实际管理员安装、XPC 登录集成、合盖热点 AI 任务、真实进程挂起、重启、升级及卸载按 `acceptance.md` 执行并另记结果。未获得实测证据前，不宣称兼容，也不启用默认常开。
