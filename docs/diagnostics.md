# 合盖资源诊断

从 1.1.0 起默认开启。保活与资源诊断有独立开关。点击菜单栏 ∞：

- **自动记录合盖诊断**：默认勾选，手动关闭会跨重启保留。
- **立即检查内存与 CPU…**：开盖时也能运行一次检查；通过两次采样计算 CPU 使用量。已有合盖记录进行中时，会补采并显示本次报告。
- **查看最近诊断报告…**：查看正在记录或最近完成的会话，在窗口中可导出 Markdown。
- **打开诊断文件夹**：查看原始 JSONL 时间序列和 Markdown 报告。后续排查可以直接让 Codex 读取这里的报告。

本机存放位置：`~/Library/Application Support/LidKeep/Diagnostics/`。该目录和文件归当前登录用户所有，分别使用 0700 / 0600 权限。不会上传，不记录命令行参数、工作内容、环境变量或完整程序路径；只记录程序名称、PID／启动标识及资源数据。查看自用诊断报告不需要每次管理员授权。

## 记录内容

每 5 秒检查一次合盖状态；识别到合盖后立即采样，然后约每 30 秒记录一次，开盖时补采并生成报告。合盖过程中观测到热状态或保活状态变化，会补采（最快每 5 秒一次）。从 1.1.4 起还记录系统休眠／唤醒通知：若合盖记录尚未开始，保存事件处理时的单次真实观测；已有合盖记录时，在处理休眠通知时补采并结束。通知处理是异步的，无法保证系统一定在挂起前完成采样，也不把事件快照当作休眠期间持续运行的证据。少于 5 秒、且没有触发休眠通知的合盖动作仍可能没有记录；快速结束的短命进程可能落在采样间隔中，报告中的峰值只是已观测峰值。

系统记录包括总内存、空闲页、压缩内存、交换区、内存压力、系统 CPU、1 分钟负载、系统热状态、电池与保活状态。进程记录覆盖本次可读且已扫描进程的内存前 8、CPU 前 8、内存增长前 8 的去重并集，并保留 LidKeep 自身及有新鲜数据的后台进程。两个管理员后台通过已有状态接口自报资源计数；其他无法读取的受保护进程会注明覆盖限制，不额外申请权限。CPU 以每核 100% 计算，多核进程可超过 100%；第一帧没有差值时记为未知；手动检查间隔只有 1 秒，后台计数尚未刷新时其 CPU 也会标为未知。

进程以 PID 和启动时间共同识别，防止旧 PID 被新进程复用后误报增长。新出现的进程单独标识。RSS 不是独占内存，不能将所有进程 RSS 直接相加当作应用实际独占；系统已占用内存含缓存，不能单凭数值大就判断泄漏。高 CPU 和高内存是排查线索，不单独证明发热原因。

## 缺口与保留范围

后台不响应时，诊断仍独立运行，电源状态标为未知。遇到系统休眠、App 退出或崩溃，采样会停止，不会为采样唤醒电脑；启动时会将未完成记录标为中断。超过 60 秒的采样间隔会在报告中标明，不能视作那段时间正常。未知读数与访问受限进程会明确显示。

单段最多 720 个快照或 8 MiB 原始数据，达到限额会自动分段；在启动或产生／更新诊断记录时清理旧记录。合盖／手动检查最多保留 20 段，系统事件另有 8 段额度，均保留最多 7 天，记录与报告合计不超过 32 MiB。总容量不足时优先清理系统事件。单次唤醒报告不会替代菜单中最近的合盖、休眠或手动报告，所有保留的事件仍可从诊断文件夹查看。关闭 App 或长期开盖而没有新记录时，不会专门唤醒程序执行清理。长时间合盖可能形成多段报告；重要记录请及时导出。

采集使用 macOS 原生接口，在 App 的独立 utility 队列运行；不会启动 ps/top/powermetrics、编译任务或额外 Claude/Codex 会话。诊断失败仅暂停诊断并显示原因，不更改电源保护策略，也不会主动结束高占用进程。
